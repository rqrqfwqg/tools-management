- 作者：许清楚（产品经理）
- 版本：v1.0（增量 PRD，仅描述相对现有 v3.0 盘点模块的变更部分）
- 关联现状：`backend/routes/materials.js`（inventory-checks）、`mobile-frontend/src/composables/useScanner.ts`、`miniapp/src/pages/inventory/`、`vue-frontend/src/views/InventoryCheck.vue`、`vue-frontend/src/views/BarcodeList.vue`

## 1. 产品目标

**一句话**：让库管员能对仓库内全部实物（含 131 把工具）进行扫码盘点，并用「左二维码 + 右文字」的新标签从技术上解决"物理识别不到条码"，扫码即得内部编码、直接匹配落账。

**验收标准（可测量）**：

1. 创建盘库单时，除备件/消耗品外，自动预置该仓库全部工具明细（G- 工具，含工具箱内的工具）；工具明细 `system_qty=1`、`actual_qty ∈ {0,1}`（逐件口径）。
2. 移动 H5 / 小程序 / PC 盘点页放开 G-/BX- 门禁：扫到 G- 编码命中工具后不再提示"不在本次盘点范围"，可正常录入；complete 时工具差异写 adjust 流水并落账。
3. H5 端解码库支持 QR 码；现场实测首扫成功率 ≥ 95%（对比旧 CODE128 标签现场 < 80% 即为显著提升）。
4. PC 端可打印「左二维码 + 右文字」标签，支持按货架 / 仓库 / 勾选批量打印，300dpi 以上清晰可扫。
5. 过渡期内旧一维码标签仍可回扫兼容。

## 4. 标签设计稿（左二维码 + 右文字）

### 4.1 版面（ASCII 示意）

```
┌─────────────────────────────────────┐
│ ┌───────────┐                        │
│ │           │   G-CFJ-1              │
│ │   QR 码   │   吹风机               │
│ │  (方形)   │   主仓库 · 1号货架      │
│ │           │   1号货架-1层           │
│ └───────────┘                        │
└─────────────────────────────────────┘
  左区：二维码          右区：文字（垂直居中）
```

### 4.2 尺寸与字段

| 项 | 规格 |
|----|------|
| 标签整体 | 推荐 **60mm × 40mm** 热敏标签（P0）；备选 50mm × 30mm（P1 尺寸切换） |
| 左区 QR | 28mm × 28mm（50×30 时 20×20mm），白底黑码，四边静区 ≥ 4 module |
| 右区文字 | 编码（必显）、名称（必显）、仓库 · 货架（P0 显示，P1 可开关）、货位（P1） |
| 编码字号 | 14–16pt 加粗，等宽字体（Courier New / monospace） |
| 名称字号 | 10–12pt 常规 |
| 仓库/货位字号 | 8–10pt 灰色 |

### 4.3 二维码内容与参数（给架构师）

| 项 | 规格 |
|----|------|
| 内容 | **仅编码内部编码**，如 `G-CFJ-1`、`BJ-PC-N-181120`、`XH-PC-N-181120`。不编码 JSON/URL/长文本（内容越短、码越稀、识别越稳） |
| 码制 | QR Code Model 2，Version 2–4（内容 ≤ 20 字符时 V2 足够） |
| 编码方式 | Byte / UTF-8（ASCII 字符直接） |
| 容错等级 | **M（15%）推荐**；对污损敏感场景可选 Q（25%） |
| 模块尺寸 | 打印后 ≥ 0.33mm，推荐 ≥ 0.4mm（决定可扫距离与抗模糊） |
| 颜色 | 纯黑 on 白；禁用反色、渐变、彩码 |
| 生成库 | 前端 `qrcode` 或 `qrcode-generator`（PC 打印页动态生成 SVG/Canvas）；后端无需生成图片（P2 可选 PNG 下载） |

### 4.4 打印方案

- 入口：PC 端 BarcodeList 页新增「二维码标签」模式，复用现有：类型 Tab（工具/工具箱/备件/消耗品）、仓库/分类/关键字筛选、勾选/全选/按货架批量选。
- 批量：按货架/仓库/勾选批量打印；131 把工具建议按货架分批贴。
- 输出：沿用现有 A4 弹窗打印（3列×8行，64×34mm 单元格可容纳 60×40 标签）；或直接对接热敏标签打印机（60×40 / 50×30 尺寸选择，P1）。
- 质量：300dpi 以上、1:1 尺寸打印，禁止缩放模糊；哑光热敏纸（避免反光）。

## 5. 扫码识别率提升技术方向

### 5.1 现状诊断

- H5 `useScanner` 仅支持 CODE_128 / EAN_13 / CODE_39 一维码（`formatsToSupport` 无 QR）；小程序 `uni.scanCode` 原生已支持二维码。
- 现场"物理识别不到条码"根因大概率是：① 一维码对倾斜/残缺/反光/遮挡敏感，扫码框需精确对齐；② 标签打印尺寸小、对比度低或材质反光；③ 现场灯光弱/手持抖动。

### 5.2 可选方案对比

| 方案 | 说明 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| A. 换 QR 二维码 | 2D 码，内容直接编码内部编码 | 方向无关、抗污损、识别率最高；手机/小程序原生支持；扫码即得 code 直接匹配 | 需改标签、打印端、解码端 | ✅ 推荐 |
| B. 优化一维码 | 加大 CODE128 尺寸/对比度/哑光纸 | 改动最小 | 仍对倾斜/部分遮挡/反光敏感，提升有限 | 过渡期保留 |
| C. 专用扫码枪/PDA | 硬件扫码 | 现场识别最强 | 需采购硬件、成本高、H5 场景仍受限 | P2 备选 |
| D. 解码库增强 | html5-qrcode 已含 ZXing/BarcodeDetector | 与 A 配套，弱光已有补光/曝光增强 | 单独做提升有限 | 与 A 一起做 |

### 5.3 推荐方案（A 为主 + B 兼容）

1. **标签改用 QR**（左码右文）：QR 内容 = 内部编码；容错 M；模块 ≥ 0.4mm；哑光热敏纸防反光。
2. **H5 解码端增加 QR**：`useScanner` 的 `formatsToSupport` 增加 `Html5QrcodeSupportedFormats.QR_CODE`；`qrbox` 改方形（如 width≈height）；扫码提示文案改"将二维码对准扫描框"。html5-qrcode 原生支持 QR（ZXing 路径），BarcodeDetector 路径同样支持，无需更换库。
3. **小程序**：`uni.scanCode` 已支持 QR，无需改动（scanType 已含 `qrCode`）。
4. **过渡兼容**：保留 CODE128/EAN13/CODE39 解码（R9），旧标签可继续扫；新标签逐步替换后一维码可下线。
5. **打印质量**：300dpi 以上、1:1 打印、哑光纸；标签贴于工具本体平整面（避免曲面/铆钉处）。

## 附：与现有实现的关键差异（供架构师对照）

1. **后端**：`POST /inventory-checks` 目前只预置 spare+consumable（materials.js L811-817）；需增加 tool 明细。`scan` 接口 L856-868 已能解析 G- 前缀并查 tools，但工具无 `stock_qty`（db.json 中 tool 无该字段）导致 `system_qty=0`、默认 actual=0；需改为逐件口径。`complete` 接口 L904-912 仅对 consumable/spare 落账 stock_qty，工具无落账分支；需新增工具差异处理。
2. **移动 H5**：`useScanner.ts` L371-375 的 `formatsToSupport` 无 QR_CODE；`qrbox` 为横向条带（L92, L327-337）；需增加 QR 并改方形。
3. **小程序**：`miniapp/src/composables/useScanner.ts` 已支持 QR（scanType 含 qrCode）；主要改 `InventoryScan.vue` 门禁（L147-151 当前扫到不在 items 即拦截）。
4. **PC**：`InventoryCheck.vue` L158 拦截 tool（"不在本次盘点范围"）；需放开并支持工具实际 0/1 录入。`BarcodeList.vue` 目前仅 CODE128 一维码（L496-507 渲染、L588-620 打印），需新增 QR 左码右文模式。
