## 一、项目背景

为加强对**部门内部各区**的工具、备件与消耗品的统一管理，开发了**工器具管理系统**（PC 网页端 + 手机网页端），用于替代传统手工登记台账，实现工具物料的数字化领用、归还、盘点和审批。

### 1.1 系统功能全景（界面可体现）

**核心业务（工具/物料全生命周期）**

- **工具管理**：工具台账（型号/数量/状态/实物图）、工具分类、按编码查询
- **工具箱管理**：工具箱台账、**装箱/拆箱**（向工具箱加入/移除工具）、工具箱条形码
- **备件管理**：备件台账（**按型号分组库存**）、低库存预警、扫码借出
- **消耗品管理**：消耗品台账、低库存预警、扫码领用
- **领用流程**：**领用购物车/领用篮** → 提交工单 → **主管审批** → 出库 → 归还清单（checklist）→ 归还/关闭
- **盘点管理**：**三阶段盘点**——创建盘点单（自动预置该仓库全部物料）→ 扫码录入实盘数 → 完成落账（差异自动调整库存并写流水）
- **库位体系**：仓库 → 货架 → 货位 三级库位，物料绑定货位
- **库存流水**：全量出入库/盘点/调整流水追溯

**系统能力与特色点**

- **扫码驱动全流程**：工具码 / 物料码 / 工具箱码（BX-{id}）统一扫码——借工具、借备件、领消耗品、盘点录入均可扫码完成；支持按编码前缀（BJ- 备件 / XH- 消耗品 / G- 工具）自动识别类型
- **条形码体系**：工具、物料、工具箱均有独立条形码，PC 端**批量生成/打印条形码**（SVG 渲染、按类型隔离）
- **低库存预警**：备件按型号分组累加比对预警量，消耗品按数量比对；仪表盘预警入口直达
- **审批流**：领用工单需主管审批（待审核/通过/驳回/归还/关闭 状态机），仪表盘待办提醒
- **弱光扫码增强**：手机端启用 BarcodeDetector 提升弱光识别，支持手电筒（torch）/曝光补偿，**手动输入降级兜底**
- **权限体系（RBAC）**：管理员 / 物料管理员 / 审批人 / 普通用户，接口级鉴权
- **手机号免密登录**：手机号验证码登录（后端已预留微信登录接口 wx-login / wx-bind-phone）
- **实物图管理**：工具/备件/消耗品支持上传实物图片

## 二、项目现状

### 2.1 系统现状

- **后端**：Node.js + Express（端口 3000，仅监听 127.0.0.1，需反向代理对外），PM2 三进程
- **PC 网页端**：Vue3 + Element Plus（22 个页面：仪表盘/工具/工具箱/备件/消耗品/购物车/工单/盘点/条形码/仓库货架货位/用户角色部门等）
- **手机网页端**：Vant4 H5（21 个视图：扫码/工具/备件/消耗品/领用/工单/盘点/我的等）
- **数据层**：**文件型 JSON 库（db.json，lowdb）**，本机存储，每日备份
- **文件存储**：上传图片存本地磁盘 uploads/
- **运行环境**：**测试云运行**（生产已部署在腾讯云段 82.156.62.59）

### 2.2 手机网页版（H5）劣势分析

结合系统真实使用场景（现场扫码借还、盘点、审批），手机网页版存在以下**结构性劣势**：

1. **扫码能力弱且不稳定**：现用 html5-qrcode（网页摄像头方案）——需浏览器授权摄像头、弱光识别差（虽有增强仍需探测 torch 能力）、**无法调用微信原生扫一扫**；不同浏览器对 getUserMedia/BarcodeDetector 支持不一，现场易"扫不出来"
2. **无统一入口**：需手动输网址/收藏网页；现场人员使用门槛高，无"扫码即开"体验
3. **无原生能力**：无法调用微信扫码；**审批/借还无消息推送**（审批人不会实时收到待办提醒，需主动打开网页看）；无离线缓存
4. **浏览器兼容风险**：微信内置浏览器/国产浏览器缓存策略、摄像头权限策略差异大，容易出现"授权失败""白屏"
5. **性能与体验**：长列表（工具/物料台账）在低端手机卡顿；无原生 tabBar 与手势
6. **登录态脆弱**：token 存 localStorage，手机清理缓存即掉登录，现场反复登录
7. **生产验证不足**：目前在测试云运行，未按生产验收（并发、带宽、稳定性未压测）

### 2.3 已有基础

- 后端**微信登录接口已就位**（`POST /api/auth/wx-login`、`POST /api/auth/wx-bind-phone`），小程序改造后端侧零新增主流程。
- 已持有 **.cn 域名**（可 ICP 备案）；计划个人主体注册小程序（免 300 元/年企业认证）。

## 三、需求

### 3.1 手机网页端 → 微信小程序

- 将手机网页端（Vant4 H5）**改造为微信小程序**，保留全部现有业务功能（扫码、领用、审批、盘点、我的等）。
- 扫码改造为 **uni.scanCode 直调系统相机**（替代 html5-qrcode 网页方案），弱光降级 + 手动输入兜底保留。
- 统一入口：微信"扫一扫"打开小程序，**扫码即用**；支持订阅消息（借还通知/审批提醒）。

### 3.2 更大容量的服务器（按系统真实需求补充）

当前测试云承载能力不足以支撑生产，结合本系统真实规模与增长，扩容需求如下：

- **多区多人并发**：部门**内部各区**多人同时使用，现场扫码借还/盘点为**高频并发操作**，要求 2 核起步、8G 内存支撑 Node+PM2 多进程
- **数据与图片增长**：工具/备件/消耗品台账 + 实物图片 + 库存流水持续增长，磁盘规划 **150G**（系统盘 + 数据盘）
- **带宽**：现场扫码、图片加载、多端访问，需 **10M 带宽**保障响应
- **微信登录会话**：wx-login 会话与 JWT 长连接，需稳定内存与带宽
- **成本约束**：数据**不采购云数据库**，仍存服务器本机 db.json + 每日备份；上传图片与备份迁 **COS 50GB** 异地

### 3.3 合规要求

- .cn 域名完成 **ICP 备案**（个人免费）→ 小程序 request 合法域名强制要求**已备案 HTTPS**。
- 申请**免费 SSL 证书**，全站 HTTPS。

## 四、设计方案

### 4.1 总体架构（根据前三项分析）

```
微信小程序（uni-app 原生，个人主体）
      │  HTTPS（request 合法域名：已备案 .cn + 免费 SSL）
      ▼
  轻量应用服务器（2C8G / 10M / 磁盘 150G，有状态部署）
  Node.js + Express + PM2（多进程，复用现有代码）
  数据：本机 db.json（lowdb）+ cron 每日备份 → 同步 COS 异地
  图片：uploads/ → COS 标准存储（50GB）
      │
      ├─> 云数据库 MySQL：不采购（本机 db.json，符合成本约束）
      └─> COS 标准存储：实物图 + 备份异地容灾
```

### 4.2 小程序改造（路线B：uni-app 原生重写）

- **页面迁移**：现有移动端 21 个视图迁移为小程序页面（登录/仪表盘/扫码/工具/备件/消耗品/领用篮/工单/盘点/我的等），组件按映射表替换（Vant4 → uni-ui/原生组件）。
- **扫码改造**：`html5-qrcode → uni.scanCode` 直调系统相机，保留弱光降级与手动输入兜底；盘点扫码复用同一扫描能力。
- **微信登录**：复用已就位的 `POST /api/auth/wx-login`（jscode2session → openid → JWT 7d），users 表补 `wx_openid / wx_unionid / wx_nickname / wx_avatar` 字段；可选 `wx-bind-phone` 绑定现有账户。
- **消息提醒**：借还通知/审批提醒走小程序订阅消息。
- **后端**：除补 wx_* 字段外，其余 90+ 接口零改动（复用现有 API）。

### 4.3 服务器与存储

- **轻量应用服务器 2C8G/10M/150G**：有状态部署 Node.js + Express + PM2 原样迁入，零改造。
- **本机 db.json + 每日备份**：cron 每日打包 → 同步 COS（防"本机备份陪葬"）。
- **COS 50GB**：实物图存储 + 备份异地。

### 4.4 域名与备案

1. .cn 域名 ICP 备案（个人主体，7–20 工作日，免费）；
2. 申请免费 SSL 证书，绑定域名强制 HTTPS；
3. 微信公众平台配置 `request / uploadFile / downloadFile` 合法域名（已备案 HTTPS 域名）。

### 4.5 割接与回滚

- 割接前 DNS TTL 降至 60 秒；选业务低峰（周末 00:00–04:00）。
- 验证四件套：接口 200 / 扫码回调成功 / 图片可访问 / 数据条数一致。
- 回滚：DNS A 记录切回旧 IP（60s TTL，1 分钟内回退）；旧 db.json 保留只读快照。

### 4.6 实施工期

- **关键路径 = 备案 7–20 工 + 微信审核 1–7 工**，整体 **50–85 日历天**。
- 开发与备案并行：纯开发约 **11–12 人日**（2 人并行 6–8 天）。
